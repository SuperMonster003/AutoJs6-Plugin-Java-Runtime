# M8-1 Worker 并行预绑定评估

## 决策

**No-go：不合入 worker 并行预绑定，继续使用“产物完成后再绑定一次性 worker”的串行路径。**

2026-08-25 在 M7-5 的 API 24/API 36 受控 AVD 与 AutoJs6 生产 Binder 路径上，依次评估了立即预绑定、
延迟到 ECJ/JAR 完成后预绑定，以及“延迟预绑定 + 单线程 D8”三个候选。候选可以保持成功执行、编译失败
不进入 worker、一次性 worker 退出和 API 24 兼容性，但 API 36 的收益方向不能稳定复现：最后一个完整
`1 cold + 10 warm` 区块的暖态 p50 仅比锁定基线少 42.5 ms，未达到 213 ms 验收线；p90 反而增加
42 ms。相邻 P–S–P 区块中，预热相对串行控制的改善方向也发生反转。

并发绑定还会扩大取消、宿主死亡、worker 先于产物连接和编译失败后的状态空间。既然性能证据没有稳定覆盖
这部分复杂度成本，本次评估回退全部运行时代码和实验测试，只保留决策记录与原始设备数据。

## 锁定环境与口径

- 设备：`emulator-5562`，`DEX_R1_API36_X64`，API 36 / x86_64；API 24 兼容性检查使用
  `emulator-5558`，`AVD_API_24`，API 24 / x86。
- 宿主、Java 输入、direct-path Activity、cache-disabled Debug 配置、行轮询与分位数算法均沿用
  [M7-5 基线](perf-baseline.md)。每个区块第一行 compiler `COLD`，之后 10 行 compiler `WARM`；
  下表仅统计暖态行。
- 每次 launch 都等待私有 JSONL 新增完整对象、确认 `:worker` 进程退出，再额外等待 750 ms。
- p50 为排序后中间两个值的算术平均；p90 为 nearest-rank。单位均为毫秒。
- AVD 未隔离宿主机调度噪声。正因存在时间漂移，最终决策同时看锁定基线和相邻控制区块，不把单个有利
  区块当成因果证据。

## 候选设计

| 代号 | 设计 | 目的 |
| --- | --- | --- |
| A | API 26+ 在编译开始时绑定 worker；API 24/25 保持串行 | 最大化 worker 启动与 ECJ/D8 的重叠窗口 |
| B | API 26+ 在 ECJ、JAR 组装及摘要完成后绑定，只与 D8 重叠 | 避免 worker 进程启动与主要 ECJ CPU 阶段竞争 |
| C | B，并通过 D8 的 executor API 把该候选的 D8 限为单线程 | 限制 D8 与 worker 冷启动同时争用 CPU；API 24 路径不变 |

实验状态机把 worker 连接和产物就绪作为两个可交换顺序的前置条件，且只允许其中第二个完成者领取一次
dispatch；retire 后晚到事件不再 dispatch。另行覆盖了 worker-first、artifacts-first、retire 和 250 次
并发竞争。它只用于验证实验候选，随 no-go 一并回退。

## API 36 结果

### 立即预绑定 A：相邻 S–P–S

`S` 为未预热的串行控制，`P` 为候选 A。三块连续执行；结果显示候选 p50 比前后两个串行控制都更慢。

| 区块 | 暖态 session 原始序列 | p50 | p90 |
| --- | --- | ---: | ---: |
| S1 | 1064, 873, 879, 851, 936, 771, 745, 749, 751, 737 | 811 | 936 |
| P / 候选 A | 976, 940, 911, 847, 986, 590, 527, 716, 1035, 913 | 912 | 986 |
| S2 | 1114, 1066, 1060, 1119, 851, 792, 862, 781, 787, 729 | 856.5 | 1114 |

立即绑定使 worker 进程创建与 ECJ、D8 同时运行，扩大了编译阶段的 CPU/内存争用，因此不再继续该方案。

### 延迟预绑定 B

候选 B 的一个探索区块为 `789, 885, 955, 916, 1011, 619, 639, 893, 873, 837`，p50/p90 为
879/955。worker 启动窗口缩短后，D8 p50 仍升到约 300.5 ms；该区块没有相邻、同调度配置的串行控制，
因此只用于进入候选 C，不作为验收证据。

### 延迟预绑定 + 单线程 D8 C：P–S–P

`P1` 和 `P2` 使用完全相同的候选 C APK，`S` 只关闭预绑定、保留相同的单线程 D8 调度。这样可避免把
D8 线程数变化误算成预绑定收益。

| 区块 | 暖态 session 原始序列 | p50 | p90 | 范围 |
| --- | --- | ---: | ---: | ---: |
| P1 | 896, 927, 929, 822, 827, 746, 702, 866, 654, 700 | 824.5 | 927 | 654–929 |
| S | 907, 998, 1166, 1080, 923, 722, 842, 995, 876, 2559 | 959 | 1166 | 722–2559 |
| P2 | 1584, 1784, 1743, 1654, 1112, 1012, 1124, 735, 775, 807 | 1118 | 1743 | 735–1784 |

P1 相对中间 S 的 p50/p90 分别少 134.5/239 ms，而 P2 分别多 159/577 ms，收益方向不能复现。
把两个 P 区块机械合并为 n=20 会得到 p50=881、p90=1654，但这会跨越明显的时间漂移，且掩盖第二次
复验失败，因此不作为接受依据。

最终 P2 与 M7-5 锁定基线的对比如下：

| 指标 | M7-5 API 36 基线 | 候选 C / P2 | 差值（候选 − 基线） | 验收 |
| --- | ---: | ---: | ---: | --- |
| 暖态 session p50 | 1160.5 | 1118 | -42.5 | **失败**：要求 ≤ -213 |
| 暖态 session p90 | 1701 | 1743 | +42 | **失败**：不得回归 |
| worker startup p50 | 424 | 531 | +107 | 描述性字段，不单独作为接受条件 |
| worker startup p90 | 661 | 714 | +53 | 描述性字段，不单独作为接受条件 |

P2 的暖态阶段 p50/p90 分别为：COMPILE 222/493、D8 352/507、LOAD 10/128、RUN 2.5/4、
TERMINATION 22.5/33。相比 M7-5，D8 和部分尾部阶段的竞争抵消了预绑定可能隐藏的等待时间。

## API 24 与功能证据

API 24/25 的 worker 启动收益上限较小，实验后半程已明确保持串行。API 24 串行回退候选的暖态
session p50/p90 为 1046.5/1244 ms；相对 M7-5 的 933/1317 ms，p50 有噪声性回归，p90 未回归。
这进一步说明不应为 legacy `DexClassLoader` 路径增加并发状态。

实验候选还完成了以下定向检查：

- API 24 与 API 36 的生产 Binder 成功执行均到达 COMPILE、D8、LOAD、RUN、TERMINATION 五阶段；
- 两台设备上的一次性 worker 在每行观测完成后退出；
- 编译错误在产物就绪前结束，未留下 terminal worker；
- worker/产物先后顺序、retire 和并发 dispatch 领取的实验单测通过。

这些检查说明候选可以继续工程化，但不能弥补性能验收失败；主线回退后仍由原有测试覆盖串行生命周期。

## 重新开启条件

除非至少满足以下条件之一，否则不重新引入本次状态机：

1. 能在隔离宿主机负载后完成多轮交错 A/B，并同时稳定跨过 p50 213 ms 与 p90 不回归门槛；
2. worker 冷启动本身有不与 ECJ/D8 争用资源的更低成本机制；
3. 未来协议允许复用已验证身份且有明确生命周期边界的 worker，并先完成新的安全评审。

当前最合理的后续项是 M8-2 多 DEX：它解决明确的能力上限，不依赖本次不稳定的调度收益。
