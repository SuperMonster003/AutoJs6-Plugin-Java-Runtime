# v0.8.0-m9

###### 2026/08/27

* `힌트` 세션 타임아웃은 기본 30초 / 하드 상한 120초를 유지하고, 동시 세션도 1개를 유지합니다 (두 번째 세션은 재시도 가능한 `BUSY`를 받음) — 두 완화 평가 모두 현 단계에서는 시행하지 않기로 결론
* `힌트` ECJ 업그레이드 평가: 최신 ECJ (3.42/3.46)는 Android에서 실행될 수 없어, 릴리스 라인은 계속 ECJ 3.26.0과 Java 8에 고정됩니다
* `새 기능` 다중 파일 소스 패키지 추가 (Protocol 1.6): 한 요청으로 2–32개의 `.java` 파일로 이루어진 정규 아카이브를 제출할 수 있으며, 경로는 `package` 선언과 정확히 대응해야 합니다. 경로 탈출, 압축 항목, 심볼릭 링크, 중복 항목은 전부 거부됩니다
* `새 기능` 임의 진입 클래스 이름을 엔드투엔드로 개방: 호출자가 ASCII 진입 단순명을 명시적으로 선택할 수 있습니다 (기본값은 여전히 `Main`). 비기본 진입 샘플 `arbitrary-entry.java` 추가
* `개선` Kotlin/JVM 지원은 자매 플러그인 Kotlin Runtime이 독립적으로 담당함을 확인. 두 저장소는 동결 프로토콜과 적합성 테스트를 공유하며 실행 시 의존성은 없습니다
* `의존성` 런타임 D8/R8을 8.13.17에서 8.13.23으로 업그레이드. 컴파일 캐시 키는 툴체인 버전에 따라 자동 무효화됩니다

# v0.4.0-m9

###### 2026/08/25

* `힌트` Android 10 이상에서 클립보드를 호출하려면 AutoJs6가 포그라운드에 있어야 합니다 (resumed 상태의 Activity 존재). 백그라운드 호출은 시스템 클립보드에 닿기 전에 확실히 실패합니다
* `새 기능` 클립보드 기능 추가 (Protocol 1.2 / Entry API 3): `clipboard().getText/setText`. 읽기와 쓰기는 두 개의 독립된 인가이며 텍스트 상한은 16 KiB
* `새 기능` 멀티 DEX 산출물 추가: 연속된 1–4개의 `classesN.dex`, 합계 32 MiB 이내. 65,536 메서드 참조의 대형 샘플이 API 24/36 실기기에서 통과 (API 26은 플랫폼 제한으로 단일 DEX 유지)
* `새 기능` 통제된 core library desugaring 추가: `java.time`과 3-인자 향상 `Stream.iterate`/`toList`를 API 24부터 사용 가능. 미지원 메서드는 컴파일 시점에 실패하며 구형 기기에서 런타임 충돌을 일으키지 않습니다
* `새 기능` 중국어 가이드 "Java Context API와 실행 경계" 추가: 전체 메서드, 반환값 타입 표, 리소스 상한, 오류 코드 의미론
* `새 기능` 취소, 반환값 계열, 컴파일 오류, 결과 초과 등의 실기기 검증 샘플 매트릭스와 원커맨드 오프라인 게이트 스크립트 `scripts/verify.ps1` / `verify.sh` 추가
* `수정` 진단 정제를 부분 치환으로 변경: 민감한 조각만 치환하고 컴파일러 메시지의 나머지는 보존합니다. 메시지 전체를 고정 문구로 떨어뜨리지 않습니다
* `수정` 컴파일 캐시 작업 레인이 타임아웃 후 쿨다운을 거쳐 1회 복구됩니다. 프로세스 재시작까지 사용 불능으로 남지 않습니다
* `개선` 한 번의 컴파일에서 생긴 여러 ECJ 오류를 소스 순서대로 한 건씩 전달 (64 KiB 진단 예산 공유)
* `개선` Debug 빌드에 사설 JSONL 관측 채널 추가 (5단계 소요 시간 / worker 콜드 스타트 / 캐시 카운터). Release 빌드는 제로 내보내기를 유지하며 테스트로 단언
* `개선` API 24/36 생산 경로 성능 기준선과 worker 사전 웜업 평가 완료 (직렬 경로 유지). 임의 진입 클래스 이름은 플러그인 측 전 링크 준비 완료
* `개선` 프로세스 간 캐시 지속화는 보안 검토 결과 불채택. 캐시 키는 계속 컴파일러 프로세스 안에서만 유효합니다
